# Softmax

## 数学定义

对长度为 C 的每一行向量 x：

```
softmax(x_i) = exp(x_i - max(x)) / Σ_j exp(x_j - max(x))
```

数值稳定版本通过减去 `max(x)` 来避免 `exp()` 溢出。

## 理论性能分析

### 算术强度

| 指标 | 公式 | 数值 |
|------|------|------|
| 数据搬运量 | 读输入 + 写输出 ≈ 2 × R × C × 4 bytes | 8RC bytes |
| 计算量 | R × (C 次比较 + C 次 exp + C 次加法 + C 次除法) | ~4RC FLOPs |
| 算术强度 | 4RC / 8RC | **0.5 FLOP/Byte** |

### Roofline 分类

算术强度约为 0.5 FLOP/Byte，Softmax 在各种输入规模下都属于典型 **内存受限**。
优化重点是提升 DRAM 带宽利用率并减少全局内存访问轮次与访存形式。

### 理论峰值

- RTX 5060 Ti DRAM 带宽：~448 GB/s（量级）
- 理想下界（单次读 x + 单次写 y）：约 2 × R × C × 4 bytes 搬运量

## 优化版本

### V0：朴素实现（每行单线程）

**文件：** `softmax_v0_naive.cu`

每个线程顺序处理整行：3 次遍历（max → exp+sum → normalize）。

- **问题：** 行内无并行，对大 C 场景浪费 GPU 资源
- **问题：** 每行对全局内存多次遍历，且对 `y` 存在中间写回与再读

### V1：减少全局访存 + 优化访存形式

**文件：** `softmax_v1.cu`

每行一个 block，线程协同做 max / sum 归约；相对 V0 仅做全局内存两类优化：

1. **减少全局读写：** 当单行长度 `cols` 可在共享内存中暂存整行 `exp` 时，避免「先写 `y=exp` 再读 `y` 归一化」的中间全局往返，对 `y` 从多次全局接触降为一次写入。
2. **优化访存形式：** 对只读 `x`（及 stream 路径下对 `y` 的读）使用 `__ldg`；在 `cols % 4 == 0` 且地址 16 字节对齐时使用 `float4` 合并访问。

`cols` 过大无法暂存时回退为三阶段 stream 路径，仍使用 `__ldg` 与 `float4`。

### V2：Online Softmax（单次累积）

**文件：** `softmax_v2.cu`

在线归一化（Milakov & Gimelshein, 2018）：在单遍扫描中维护运行中的 `max` 与 `sum`，发现更大 `max` 时对历史部分和重缩放。

- **核心思路：** 相对多遍遍历，减少全局内存遍历次数
- **数值稳定：** 通过在线重缩放保证等价于「先减 max 再 exp」的稳定 softmax

### V3：Warp Shuffle + 向量化

**文件：** `softmax_v3.cu`

面向 **单 warp 可覆盖行宽** 的场景（如 `cols ≤ 128`）：

- `__shfl_sync` / `__shfl_down_sync` 做 warp 内 max/sum 归约，减少共享内存
- `float4` 向量化加载/写回，降低访存指令与事务数

### cuDNN 参考

**文件：** `softmax_cudnn_ref.cu`

`cudnnSoftmaxForward`（`CUDNN_SOFTMAX_ACCURATE` 模式）作为库基线。

## 横向对比

### 关键结论

1. **V2 Online Softmax** 在大矩阵场景下性能最佳，512×4096 达到 **470 GFLOPS**
2. **cuDNN** 在小矩阵场景有固定开销，不适合小 batch 大 hidden dim
3. **V3 Warp+Vec** 在中等规模矩阵表现优秀，特别是 256×4096 达到 **246 GFLOPS**
4. **V0 Naive** 受限于行内串行计算，SM 利用率低
