# Softmax CUDA 优化复盘（面试版）

## 1. 背景与目标

Softmax 是 Transformer/LLM 的关键算子之一，执行频率高，对端到端时延影响明显。  
本项目目标不是只“跑通”，而是建立一条可讲清楚的性能优化链路：

- 从 `v0` 到 `v3` 的逐步演进；
- 每一步都解释“上个版本问题是什么、为什么要换方案”；
- 用数据证明优化效果；
- 保留 Nsight 分析位，后续可补图形成完整证据链。

---

## 2. 数学定义与性能预判

对每一行长度为 `C` 的向量 `x`：

```
softmax(x_i) = exp(x_i - max(x)) / sum_j exp(x_j - max(x))
```

减去 `max(x)` 是数值稳定的基础（避免 `exp` 溢出）。

### 2.1 算术强度估算

| 指标 | 估算 | 量级 |
|------|------|------|
| 数据搬运 | 读 `x` + 写 `y` | `~8RC bytes` |
| 计算量 | 比较 + exp + 加法 + 除法 | `~4RC FLOPs` |
| 算术强度 | `4RC / 8RC` | `~0.5 FLOP/Byte` |

结论：Softmax 是典型 memory-bound 算子。主优化方向应是：

- 减少全局内存往返；
- 提升访存并行度/访存形式（向量化、只读路径）；
- 降低归约开销。

## 3. 版本演进（重点：上一版问题 -> 为什么更新）

## 3.1 v0：朴素实现

**文件：** `softmax_v0_naive.cu`

### 上一版问题（基线本身）

- 每行单线程串行做 `max -> exp/sum -> normalize` 三遍扫描；
- 行内没有并行，SM 利用率低；
- 全局内存读写轮次多。

### 设计价值

- `v0` 用于建立正确性与性能下限，便于量化后续收益。

## 3.2 v1：共享内存与访存形式优化

**文件：** `softmax_v1.cu`

### v0 的问题

- 多次全局读写，尤其中间结果处理低效；
- 缺少线程协同归约。

### 为什么升级到 v1

- memory-bound 算子最先应减少 DRAM 往返；
- 每行一个 block 的协同归约改造成本低、收益直接。

### 关键改动

- 行内线程协同完成 `max/sum`；
- 可缓存时避免中间 `y` 的“写回再读”；
- 使用 `__ldg` 与 `float4` 优化访问路径。

## 3.3 v2：Online Softmax（单遍思路）

**文件：** `softmax_v2.cu`

### v1 的问题

- 仍存在多阶段扫描开销；
- 对大 `C` 场景，全局访问轮次仍偏高。

### 为什么升级到 v2

- Online Softmax 能把“稳定性 + 归一化统计”融合到单遍累积逻辑中；
- 目标是降低遍历次数并保持数值稳定。

### 关键改动

- 维护运行中的 `max` 与 `sum`；
- 当出现更大 `max` 时重缩放历史和；
- 保持与稳定 softmax 等价的数值路径。

## 3.4 v3：Warp Shuffle + 向量化

**文件：** `softmax_v3.cu`

### v2 的问题

- 归约阶段仍有共享内存同步开销；
- 在部分小行宽场景，warp 内通信可以更轻量。

### 为什么升级到 v3

- 对 `cols` 较小（如 `<=128`）场景，warp shuffle 往往比 shared-memory 归约更高效；
- 配合向量化可进一步降低访存指令数。

### 关键改动

- 采用 `__shfl_sync` / `__shfl_down_sync` 进行 warp 内归约；
- 保留 `float4` 访问模式。

## 3.5 cuDNN 参考

**文件：** `softmax_cudnn_ref.cu`

- 使用 `cudnnSoftmaxForward` 作为库基线；
- 用于判断自研 kernel 在不同规模下的竞争力。

## 5. 结果解读（可直接面试口述）

1. **v0 -> v1**：通过 block 协同和访存优化，性能显著提升，证明“先抓访存”方向正确。  
2. **v1 -> v2**：在线归一化在多数中大规模上继续提升，说明“减少遍历轮次”有效。  
3. **v2 -> v3**：在 warp 友好场景（尤其部分大列配置）`v3` 表现最强，但并非所有规模都绝对领先。  
4. **与 cuDNN 对比**：小规模时库开销明显；中大规模下自研内核与库各有优势，体现了“场景依赖型最优”。
