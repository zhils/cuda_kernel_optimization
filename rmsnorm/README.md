# RMSNorm CUDA 优化复盘

## 1. 问题背景与目标

RMSNorm 是大模型中非常高频的归一化算子，计算定义如下：

```
y = x / sqrt(mean(x^2) + eps) * gamma
mean(x^2) = (1 / C) * sum_{i=0}^{C-1}(x_i^2)
```

本项目的核心目标不是“功能可用”，而是“性能可解释、优化路径可复现”：


---

## 2. 理论判断：为什么先盯访存

### 2.1 算术强度估算

| 指标 | 估算公式 | 量级 |
|------|----------|------|
| 数据搬运 | 读 `x` + 读 `gamma` + 写 `y` | `~12RC bytes` |
| 计算量 | 平方和 + 归一化缩放 | `~4RC FLOPs` |
| 算术强度 | `4RC / 12RC` | `~0.33 FLOP/Byte` |

结论：算术强度低，属于典型 memory-bound 算子。  
因此优化主线应该是：

- 减少全局内存往返；
- 提升访存并行度与访存形式（向量化、对齐）；
- 降低归约开销与同步开销。

## 2. 版本演进

## 2.1 V0（Naive）  

**文件：** `rmsnorm_v0_naive.cu`

### 上一版问题（基线本身）

- 每行单线程串行完成平方和与写回；
- 行内并行度几乎没有，SM 利用率低；
- 对 `x` 的读取复用差，吞吐受限。

### 当前实现

- 作为正确性和性能基准，不做复杂优化。

### 小结

- V0 的价值是建立可验证的性能与正确性下限；
- 后续版本应能证明相对 V0 的加速且保持误差在阈值内。

## 2.2 V1（共享内存 Staging + 串行归约）

**文件：** `rmsnorm_v1.cu`

### V0 的主要问题

- `x` 访问有重复；
- 归约和写回阶段没有充分利用 block 内协同；
- 全局访存事务数偏高。

### 为什么升级到 V1

- RMSNorm 的核心是 memory-bound，先优化访存收益最大；
- 先做"低风险高收益"改动（共享内存staging、向量加载）。

### V1 的关键改动

- **1维 block 设计**: 128 线程 = 4 个 warp，每个 warp 处理一行数据；
- **共享内存 staging**: 数据先加载到共享内存，后续计算从共享内存读取，减少重复全局读；
- **串行归约**: 每个 warp 的 lane 0 串行计算该行的 sq_sum；
- **float4 向量化**: 使用 float4 加载和写回，提升内存带宽。

### 结果

- 小中尺寸收益明显，是后续版本的基础。

## 2.3 V2（共享内存 Staging + Warp 归约）

**文件：** `rmsnorm_v2.cu`

### V1 仍存在的问题

- 归约阶段由 lane 0 串行执行，成为瓶颈；
- 对于大 hidden dim，串行归约开销显著。

### 为什么升级到 V2

- Warp 级归约利用 warp shuffle 指令，可并行完成归约；
- 相比串行归约，能更好地利用 warp 内所有线程。

### V2 的关键改动

- **1维 block 设计**: 128 线程 = 4 个 warp，每个 warp 处理一行数据；
- **共享内存 staging**: 数据先加载到共享内存，后续计算从共享内存读取；
- **Warp 归约**: 使用 `__shfl_down_sync` 进行 warp shuffle 归约，所有线程参与计算 sq_sum；
- **float4 向量化**: 使用 float4 加载和写回，提升内存带宽。

### 结果

- 在 `1024x1024` 这类中大规模上表现最好（单核版本中）。

## 2.4 V3（Weight 共享内存 + 直接全局访存）

**文件：** `rmsnorm_v3.cu`

### V2 的问题

- 共享内存 staging 需要存储整行 `x` 数据，对于大 hidden dim 会超出共享内存限制；
- 数据先加载到共享内存再读取，增加了一次额外的访存路径。

### 为什么升级到 V3

- Weight 是只读且被所有行复用的，放入共享内存可减少全局访存；
- `x` 数据使用 `__ldg` 通过只读缓存（texture cache）加载，无需共享内存中转；
- 减少共享内存使用量，支持更大的 hidden dim。

### V3 的关键改动

- **Weight 放共享内存**: 只将 weight 加载到共享内存，所有行复用；
- **x 直接从全局内存读取**: 使用 `__ldg` 通过只读缓存加载 x，避免共享内存 staging 开销；
- **Warp 归约**: 使用 `__shfl_down_sync` 进行 warp shuffle 归约；
- **float4 向量化**: 使用 float4 加载和写回，提升内存带宽。

### 结果

- 在大部分场景下表现最优，尤其适合大 hidden dim 场景。

## 3.3 相对 CUB 性能比率

| 矩阵规模 | v0/CUB | v1/CUB | v2/CUB | v3/CUB |
|----------|--------|--------|--------|--------|
| 128×128 | 0.69x | 2.06x | 1.18x | 2.30x |
| 256×256 | 0.18x | 1.08x | 1.35x | 1.35x |
| 512×512 | 0.11x | 1.32x | 1.41x | 1.18x |
| 1024×1024 | 0.06x | 1.32x | 1.46x | 1.44x |
| 4096×4096 | 0.41x | 1.49x | 1.45x | 1.51x |

### 结果解读

- 小尺寸（128×128）：`v3` 表现最佳（2.30x），`v1` 次之（2.06x），均领先CUB；
- 中小尺寸（256×256）：`v2` 和 `v3` 并列最佳（1.35x），`v1` 略优CUB（1.08x）；
- 中等尺寸（512×512）：`v2` 表现最佳（1.41x），`v1` 次之（1.32x），`v3` 略优CUB（1.18x）；
- 大尺寸（1024×1024）：`v2` 表现最佳（1.46x），`v3` 次之（1.44x），`v1` 略优CUB（1.32x）；
- 超大尺寸（4096×4096）：`v3` 表现最佳（1.51x），`v1` 和 `v2` 接近（1.49x、1.45x）；
- 结论是：在当前实现与测试设置下，`v3` 在大部分场景下表现最优，`v2` 在中等规模表现最佳，`v1` 在各规模下都稳定优于CUB。
